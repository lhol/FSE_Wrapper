# v0.0.16 Specification

## Overview

Publish FSE_Wrapper to Maven Central and nuget.org so consumers can install via standard package managers.

---

## Tasks

### 1. Maven Central Publishing
- [ ] Sign up / configure OSSRH Sonatype account at https://central.sonatype.com/
- [ ] Generate GPG signing key, store as GitHub secret `GPG_PRIVATE_KEY` and `GPG_PASSPHRASE`
- [ ] Add to `pom.xml`:
  - `maven-gpg-plugin` (sign artifacts)
  - `maven-source-plugin` (attach sources JAR)
  - `maven-javadoc-plugin` (attach javadoc JAR)
  - Distribution management section with OSSRH URLs
- [ ] Add `release-maven.yaml` workflow that runs on `v*.*.*` tags:
  - Sets version from tag
  - Signs and uploads to OSSRH staging
  - Promotes staging to release
- [ ] Verify `pom.xml` has all required fields:
  - `<licenses>`, `<developers>`, `<scm>`, `<description>`

### 2. NuGet Trusted Publishing (OIDC)
- [ ] On nuget.org: Account → API Keys → Trusted Publisher → link to `lhol/FSE_Wrapper` repo + `release.yaml` workflow
- [ ] Remove any placeholder/legacy API key approach
- [ ] Test with dry-run: `dotnet nuget push ... --skip-duplicate`
- [ ] Document the exact policy configuration in README

### 3. CHANGELOG.md
- [ ] Create `CHANGELOG.md` with entries for v0.0.1 through v0.0.16
- [ ] Add GitHub Actions step that auto-generates release notes from conventional commits
- [ ] Use `gh release create --generate-notes` (already done) — verify format is useful

### 4. Javadoc + Sources
- [ ] Ensure all public Java API methods have Javadoc
- [ ] Test that `mvn javadoc:javadoc` succeeds without errors
- [ ] Attach `-sources.jar` and `-javadoc.jar` to GitHub Release as artifacts

### 5. Integration Smoke Tests
- [ ] After NuGet publish: create a minimal C# project that adds `Huff0.Net`, runs compress/decompress
- [ ] After Maven publish: create a minimal Java project that adds `FSE_Wrapper`, runs compress/decompress
- [ ] Run these as separate CI jobs that trigger after the publish jobs succeed

---

## Notes

- Maven Central requires GPG signing; this is a one-time setup per machine/account
- NuGet OIDC trusted publishing is the preferred approach (already in `release.yaml`); just needs the policy created on nuget.org
- Starting with v0.0.16 as a pre-release before bumping to 1.0.0

## Dependencies

- Requires v0.0.15 to be released and verified first
- Requires OSSRH account approval (can take 1-2 business days for new accounts)
