## Tasks

### 1. Maven Central Publishing — via Central Publisher Portal
**Note:** OSSRH was shut down on 2025-06-30. All publishing now goes through
the [Central Publisher Portal](https://central.sonatype.com/) using the
`central-publishing-maven-plugin` (not the old `nexus-staging-maven-plugin`).

The plugin and metadata are already configured in both `pom.xml` and `java-panama/pom.xml`.
The workflow `release-maven.yaml` is ready. Only manual one-time setup remains:

- [ ] **Step 1** — Log in to https://central.sonatype.com/ (GitHub login works)
- [ ] **Step 2** — Claim namespace `org.karenta` (My Namespaces → Add Namespace)
- [ ] **Step 3** — Generate a User Token: Account → User Token → Generate
  - Save both the *Username* and *Password* shown (cannot be retrieved later)
- [ ] **Step 4** — Add GitHub repository secrets (Settings → Secrets → Actions):
  - `CENTRAL_TOKEN_USERNAME` — token Username from Step 3
  - `CENTRAL_TOKEN_PASSWORD` — token Password from Step 3
  - `GPG_PRIVATE_KEY` — armored private GPG key (`gpg --armor --export-secret-keys <ID>`)
  - `GPG_PASSPHRASE` — passphrase for the GPG key
- [ ] **Step 5** — Generate GPG key if you don't have one:
  ```bash
  gpg --full-gen-key                        # RSA 4096, set a passphrase
  gpg --list-secret-keys --keyid-format=long
  gpg --armor --export-secret-keys <KEY_ID> # → paste as GPG_PRIVATE_KEY secret
  gpg --keyserver keyserver.ubuntu.com --send-keys <KEY_ID>
  ```
- [ ] **Step 6** — Create GitHub environment named `release` (Settings → Environments)
- [ ] Trigger a `v*.*.*` tag and verify both JNI + Panama JARs appear on
  https://central.sonatype.com/publishing/deployments

### 3. NuGet — GitHub Packages — MISSING ❌
**Why packages don't appear at https://github.com/lhol/FSE_Wrapper/packages:**
nuget.org and GitHub Packages are two completely independent registries.
Publishing to nuget.org does NOT populate the GitHub Packages feed
(`https://nuget.pkg.github.com/lhol/index.json`).

Implementation in `release.yaml`:
- [ ] Add `packages: write` to the top-level `permissions` block
- [ ] After the existing nuget.org push, add a GitHub Packages push step:
  ```yaml
  - name: Push to GitHub Packages
    run: |
      dotnet nuget push nuget-out/*.nupkg \
        --api-key "${{ secrets.GITHUB_TOKEN }}" \
        --source "https://nuget.pkg.github.com/lhol/index.json" \
        --skip-duplicate
  ```
- [ ] No extra secrets needed — `GITHUB_TOKEN` is sufficient and automatically provided
- [ ] Verify packages appear at https://github.com/lhol/FSE_Wrapper/packages after next release
